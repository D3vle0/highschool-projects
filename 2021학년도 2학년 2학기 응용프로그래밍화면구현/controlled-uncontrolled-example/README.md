# Controlled vs Uncontrolled Component

React에서 폼(Form) 요소를 다루는 두 가지 방식인 **제어 컴포넌트**와 **비제어 컴포넌트**의 핵심 장단점 요약입니다.

## 1. 제어 컴포넌트 (Controlled)
> React의 `state`로 입력값을 직접 관리하는 방식

- **장점**
  - **실시간 유효성 검사**: 글자 수 체크, 입력 형식 검사 등을 타이핑 즉시 반영 가능
  - **입력값 가공 용이**: 전화번호 하이픈 자동 추가, 대소문자 변환 등 제어 편리
  - **UI 실시간 연동**: 입력 내용에 따라 제출 버튼 활성화/비활성화 처리 쉬움
- **단점**
  - **잦은 리렌더링**: 한 글자 입력할 때마다 컴포넌트가 다시 렌더링됨
  - **코드량 증가**: 입력 필드마다 상태(`state`)와 `onChange` 핸들러가 필요함

## 2. 비제어 컴포넌트 (Uncontrolled)
> React 상태 대신 DOM 자체가 값을 보관하고, `ref`로 필요할 때 조회하는 방식

- **장점**
  - **렌더링 성능 최적화**: 입력 시 리렌더링이 발생하지 않아 대규모 폼에서 빠름
  - **간결한 코드**: 상태를 일일이 관리하지 않고 제출 시점에만 값을 읽어옴
  - **필수적인 경우 지원**: 파일 업로드(`<input type="file" />`)나 서드파티 DOM 라이브러리 연동에 적합
- **단점**
  - **실시간 제어 불가**: 타이핑 도중 실시간 검증이나 즉각적인 UI 변경이 어려움
  - **명령형 코드**: React 방식보다는 `ref.current.value` 등 직접적인 DOM 접근 필요

## ⚖️ 한눈에 비교

| 구분 | 제어 컴포넌트 (Controlled) | 비제어 컴포넌트 (Uncontrolled) |
| :--- | :--- | :--- |
| **데이터 주체** | React `state` | 브라우저 DOM |
| **값 접근** | `this.state.value` | `this.inputRef.current.value` |
| **리렌더링** | **입력할 때마다 발생** | **발생 안 함** |
| **실시간 검증** | 매우 쉬움 | 어려움 |
| **권장 사용처** | 대부분의 일반적인 폼 (React 권장) | 단순 폼, 파일 업로드, 고성능 대형 폼 |
